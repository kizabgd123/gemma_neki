# Research: EDA and Leakage-Safe Feature Engineering

**Date**: 2026-05-13

## 1. Executive Summary
The S6E5 competition involves predicting if a driver will pit on the next lap. The dataset is clean (no missing values) and consists of 439,140 samples with a binary target (PitNextLap). The target distribution is approximately 80.1% (No Pit) and 19.9% (Pit). The project contains an agentic orchestration framework that can be adapted for automated model training and evaluation.

## 2. Technical Context
- **Data Location**: `/home/kizabgd/.gemini/tmp/memorijada/data/` containing `train.csv`, `test.csv`, and `sample_submission.csv`.
- **Target Variable**: `PitNextLap` (float64, 0.0 or 1.0).
- **Features**:
  - Categorical: `Driver` (887 unique), `Compound` (5 unique), `Race` (26 unique).
  - Numerical/Ordinal: `Year`, `PitStop`, `LapNumber`, `Stint`, `TyreLife`, `Position`, `LapTime (s)`, `LapTime_Delta`, `Cumulative_Degradation`, `RaceProgress`, `Position_Change`.
- **Existing Framework**: `agents/` directory contains `AnalysisAgent`, `CodingAgent`, and `CLIAgent`. `CLIAgent` supports `python3` and `pip` for script execution.

## 3. Findings & Analysis
- **Target Distribution**: Imbalanced (80/20). Stratified sampling is required for CV.
- **Categorical Cardinality**: `Driver` has high cardinality (887). May require target encoding or embeddings.
- **Data Cleanliness**: 439,140 rows, 0 nulls. High-quality synthetic data (Playground Series).
- **Leakage Risk**: Features like `LapTime_Delta` and `Cumulative_Degradation` are likely calculated using previous laps. Must ensure no "future" information is leaked from the target. Since this is a "next lap" prediction, we must be careful with features that might implicitly include the pit stop event itself.

## 4. Technical Constraints
- **Hardware**: Must be optimized for Kaggle GPU/CPU environments.
- **Tools**: `LGBM`, `XGB`, `CatBoost` are the targets for the ensemble.
- **Framework Compatibility**: The existing `CLIAgent` timeout is 60 seconds. Heavy training tasks will need to be run as background processes or in smaller chunks if using the agentic runner directly.

## 5. Architecture Documentation
- The project follows a **Plan-Act-Verify** architecture.
- `ModelRouter` handles fallback between Gemini and Mistral models.
- `execution/engine.py` implements a DAG-based topological task runner.
